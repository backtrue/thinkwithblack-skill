# 文章轉多平台社群貼文

以使用者提供或目前對話已確認的文章為原稿，交付可直接貼上的各平台版本。使用者指定平台、語言或格式時，以當次要求為準

## 來源與範圍

- 優先沿用對話中的完整核准稿；提供檔案時讀取該檔，只有網址時實際讀取文章內容
- 先保留原稿的核心問題、作者立場、具體案例、工具用途、來源及行動呼籲，再依平台刪減與重排
- 不新增作者經歷、成效數字、功能承諾或官方說法。改寫不把推論升級成事實
- 保留品牌、產品、Skill 名稱與術語大小寫，例如 Safe Zone、ThinkWithBlack、GitHub、LinkedIn
- 沿用已確認的文章、官方來源與 GitHub 連結，不編造網址。若缺少連結，先交付可完成的本文並指出缺少項目，不填假連結
- 原稿若介紹套件中的一個 Skill，保留它與整套工具的關係，不改寫成獨立產品

## 平台交付規則

使用者只說「社群版」時，預設一次交付 Facebook、Threads、Instagram、X、LinkedIn 五個平台，不只給單一泛用貼文。使用者明確限定平台時，依指定範圍交付

### Facebook：繁體中文，本文與連結分開

交付兩個可分別複製的區塊：

1. **Facebook｜本文**：從原稿的實際情境切入，交代問題、讀者需要知道的觀念或做法，再接上工具或文章的價值與行動呼籲
2. **Facebook｜留言連結**：集中列出完整文章、工具或 GitHub、必要官方來源，每個網址附簡短用途

本文不放裸網址或 Markdown 超連結；需要導流時寫「完整文章與工具連結放留言」。這是使用者的版型偏好，不宣稱分開放連結能提高觸及

用台灣口吻與連貫段落，不把每一句拆行。保留原作者合理的情緒與實務要求，避免用制式宣傳語取代個人觀點

### Threads：繁體中文

- 從原稿的一個具體問題或實務觀察切入，用自然對話口吻推進，不直接複製 Facebook 長文
- 先完成可獨立閱讀的主貼文；需要補充例子、方法或來源時，再交付清楚編號的後續串文
- 連結放在合適的主文或最後一則，區分每則可直接貼上的文字，不把編輯備註混入串文
- 檢查每則篇幅，需精確平台限制時查當下官方說明，不假設帳號具備額外長文功能

### Instagram：繁體中文

- 預設交付貼文說明文字，以首段點出問題或讀者會看到的重點，再補充做法與 CTA
- 若已有配圖，文字須與圖片內容及順序一致，不提不存在的圖片、輪播頁或操作示範
- 需要輪播文案時，另列每頁文字與順序，與貼文說明文字分開；不把文字規劃宣稱為已完成圖片
- 不預設貼文內網址可點擊，也不在尚未確認個人檔案連結時寫「點個人檔案連結」。沿用已確認的導流位置；沒有時使用可搜尋的文章、品牌或工具名稱，不虛構留言自動私訊功能

### X：英文

- 直接交付自然英文，保留原意，不逐句硬翻中文
- 選出一個明確切入點。能單篇說清楚就用單篇，需要例子、流程與 CTA 才拆成編號串文
- 串文每則可獨立理解，依序推進，不把同一段話換句話重複
- 預設採一般短貼文篇幅，不假設帳號有長文權限。含編號與網址的每則都要檢查長度；若需精確字元上限或網址計數規則，查當下官方說明，不以字數目測宣稱通過
- 連結可放最後一則，並保持 CTA 簡潔

### LinkedIn：英文

- 以專業讀者的實際工作問題切入，說清楚案例、工作流程與能帶回團隊使用的做法
- 比 X 保留更多背景與操作細節，不直接貼上 X 串文，也不只把 Facebook 全文逐句翻譯
- 用自然段落，必要時以短清單呈現流程；結尾放文章、工具及相關來源連結
- LinkedIn 編輯器內換行使用 Shift+Enter；段落之間連按兩次 Shift+Enter，保留一個空行，避免段落連在一起
- 儲存後讀回公開貼文並檢查畫面，確認段落空行確實保留，不能只確認文字存在
- 若導向的文章或教材是繁體中文，簡短註明，讓英文讀者知道內容語言

## 必要潤稿流程

先完成各平台初稿，再依語言載入並實際執行對應 Skill，最後核對原稿與平台格式後交付：

- Facebook、Threads、Instagram：使用 [speak-human-tw](references/speak-human-tw/METHOD.md)，校準台灣用語、作者口吻、段落銜接與節奏
- X、LinkedIn：使用 [speak-human-en](references/speak-human-en/METHOD.md)，以自然英文重整句子與論述，保留作者立場、事實與證據強度

潤稿是必要步驟，不以「自行檢查語感」取代，不只在文件中提及 Skill 名稱。遵循各 Skill 根層指示，依當次改寫分支讀取所需參考文件，不複製整份潤稿規則到本文件

若指定 Skill 無法取得，指出缺少的名稱與位置，保留已完成初稿，不將未潤稿版本標示為完成版

潤稿後重新檢查 Facebook 本文與連結分離、五平台語言、串文篇幅與 CTA，避免潤稿改回不符合平台的格式。交付成品，不附例行潤稿報告

## 文字與配圖

- 段落結尾不自動加中文句號，同一段內需要分句時正常使用。英文維持自然英文標點
- Hashtag 只選與內容直接相關的少量標籤，不用堆疊標籤補篇幅
- 原稿已有核准配圖且使用者需要配圖安排時，依內容建議順序；不因為改寫貼文就自行新增圖片或沿用已被取消的配圖
- 不把「皮卡」、處理說明、審核筆記或內部檔案路徑混進可直接發布的貼文本文

## 完成前核對

- 指定平台是否齊全；未指定時是否包含 Facebook、Threads、Instagram、X、LinkedIn
- Facebook 本文是否完全沒有連結，留言連結是否另列
- Facebook、Threads、Instagram 是否為繁中；X、LinkedIn 是否為英文，且各自針對平台重寫
- 繁中與英文版本是否分別完成 speak-human-tw 與 speak-human-en 潤稿及保真回讀
- Instagram 的配圖描述與導流位置是否符合實際素材及已確認設定
- 原稿的品牌名稱、術語大小寫、數字、功能、案例與來源是否保真
- CTA 是否指向正確的文章與整套工具，網址是否原樣保留
- X、Threads 是否過長或需要拆串；各版本是否出現重複敘述與翻譯腔

直接交付完成版，不預設先交計畫或詢問平台偏好

## 改寫與發布

「改成社群版」「寫成貼文」交付文案，不自動到帳號發布。使用者明確要求實際發布時，沿用已授權的平台與帳號，不重問已有資訊；缺少實際發布目的地時才補問

發布 Facebook 時，先發本文，再把連結放到該貼文留言。發布後分別讀回本文與連結留言；其他平台也讀回公開成品與貼文網址，確認文字、語言及連結正確，才回報已發布
