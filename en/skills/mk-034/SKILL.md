# MK-034 | Turning events into problem awareness

For a regular chat, upload `packs/mk-034.md`. It includes the shared rules, this method, and required references

## Purpose

This skill delivers: **Hypotheses about the problems each event raises**

Task stages are analytical categories, not a claim that every customer follows the same path

## Required inputs

Provide: The product or service, customers' own words, existing pages, and actions the company can support

## Method

1. Move one step beyond the event and ask "What problem does this make the person aware of?"
2. Problem awareness should naturally lead to subsequent searches, without jumping directly to a brand/product
3. If connecting an event to a problem requires inventing substantial story detail, label it a hypothesis pending validation

## Calculations and interpretation

Search phrases and paths are planning hypotheses; check them against real search terms and evidence of how pages support the need

## Verification cases

**MK-034-C05 | An ad promotes a service that the page does not explain**

Expected: Record a verifiable promise gap; do not immediately conclude it caused all abandonment

**MK-034-C06 | No verbatim customer statements are available**

Expected: Produce only a need map awaiting validation, not a claimed finding from actual research
