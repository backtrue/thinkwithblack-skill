# MK-166｜Meta Creative Test Grouping

For a regular chat, upload `packs/mk-166.md`; it includes the shared rules, this method, and required references

## Purpose

This Skill delivers: **Comparable test groups without confounding**

Use actual tools and current official specifications to establish platform options and placement availability; old course screenshots do not establish current capabilities

## Required Inputs

Actual creative/copy variants for a Persona, comparison purpose, held conditions/test variable, primary outcome/window and resources

## Method Steps

1. Prepare multiple copy/creative directions for the same Persona, with the central aim of discovering which messages and assets interest the audience
2. The course prefers manually creating multiple ad tests rather than making the built-in A/B test the default
3. Run all three directions of the three-line copy, labeling the creative/copy direction in ad names for later CTR comparison
4. For each group, list audience, copy or creative, placement, budget, and observation window; identify held conditions and the factor compared; record the primary metric and denominator in advance and leave an unspecified window pending
5. Manually creating groups does not ensure random allocation or equal exposure; record allocation and delivery differences and mark insufficient evidence accordingly; CTR measures click response and does not replace sales outcomes

## Activation Conditions and Full Question Scope

Use this Skill directly when the user wants to organize a known audience and existing copy/creative directions into comparable test groups. Preserve each group's changed variables, fixed conditions, primary result definition, and creative names. If only a draft grouping is needed, provide a comparable arrangement and missing items even when budget is unknown

If “How should I test ads?” actually asks about daily spend, ABO/CBO budget structure, when to increase/decrease budget, loss limits, winner thresholds, or creating ads, first identify the requested outcomes; creative grouping cannot replace those decisions. When the original question asks for multiple outcomes, check capabilities for each, rather than claim one Skill solves the whole question simply because a creative testing method exists

Hand off integrated reports and cost calculations only when the user requests them or they are necessary to complete this question; finish once the required test groups have been delivered

## Verification cases

**MK-166-A1 | A receives substantial delivery while B has no spend**

Expected: Mark B as insufficient evidence, record the allocation difference, and do not label its creative worse
