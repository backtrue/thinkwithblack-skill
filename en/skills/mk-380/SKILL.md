# MK-380 | RFM Segment Naming

For ordinary chat, upload `packs/mk-380.md`, which includes the shared rules, this method, and required references

## Purpose

This skill delivers: **Definitions for segments such as loyal, high-potential, and due for reactivation**

Do not rank RFM results from different observation periods as if they shared one basis; separately verify the purpose and authorization for any list export or use

## Required inputs

Raw inputs: verified R/F/M scores and three-digit codes, interval/window version, approved brand label map; the embedded course example retains unresolved source entries

## Method steps

1. Verify R/F/M concatenation and rule version. Approved brand mappings take precedence; adopting the course example requires a stated source and approved use, not an assumed universal brand policy
2. Match each code exactly. One unambiguous match yields a label; none is unmapped and multiple matches are conflicts. Do not infer dormancy from sums, nearest codes or all unlisted records
3. For the embedded source table, match explicit three-digit codes. Literal 511.423 and 1~ lack unambiguous definitions; retain them pending an approved expansion rather than split them or label every 1-prefix member
4. Deliver raw RFM, scores, code, matched row, label, map version and task. Course channel suggestions are candidates; actual contact follows eligibility and need, not the label alone
5. Recompute groups after interval, M, window or map changes; a map-only correction rematches the same verified code. New eligibility/needs revise actions instead of forcing the old-group offer
