# MK-040 | Matching needs to ad formats

For a regular chat, upload `packs/mk-040.md`. It includes the shared rules, this method, and required references

## Purpose

This skill delivers: **Task allocation across search, video, and other formats**

Task stages are analytical categories, not a claim that every customer follows the same path

## Required inputs


Available raw records: actual customer queries or remarks, products/services, existing assets and pages, and feasible next actions

## Method Steps

1. Use actual queries, customer remarks, and existing pages to identify the job, missing answer, and acceptable next action. Separate search records from interviews; imagined queries are not observed search demand
2. Consider search when an explicit query exists and the page answers it with a usable next step. Consider video when understanding the difference requires seeing a process and genuine demonstration assets exist
3. Consider Demand Gen when the need arises during browsing and matching contextual assets and a destination exist. A PMax candidate also requires a defined valuable conversion, usable measurement, and fulfillable destination; wanting orders is insufficient
4. When several formats fit, choose the first test by the missing contact point, assets, budget, and known costs. Without comparable costs, offer bounded tests rather than inventing one best format. Prepare the destination or narrow the promise if no useful next action exists
5. If a supposed query proves to be internal speculation, downgrade search to an unverified candidate. If existing text and images already explain the product, video is no longer required. Request only a raw customer question or asset that distinguishes the candidates

## Calculation and Interpretation

Deliver the chain: customer wording → needed answer → format → existing asset/page → initial action. Separate format fit from advertising performance

Check example (hypothetical): repeated questions about how installation works plus a real demonstration support video. Raw remarks instead reveal questions about local installation availability; switch to a service-area page serving those explicit queries
