# Rules for using the free methods

Use these materials in an ordinary AI conversation to complete one clearly defined task with the data supplied by the user

For work on a specific brand, read the latest relevant sections of that brand’s context first and reuse known information without asking again. On the first task, inventory the supplied statements, attachments, and authorized sources for the brand, products, Persona buying-motivation evidence, positioning, voice, objectives, and constraints. Merge newly confirmed facts with their sources, confirmation basis, and dates while retaining other fields and earlier versions. Keep hypotheses, unverified psychology, and one-task diagnoses in the task record. Read again when the brand, facts, or version changes, then continue the original task

## Each question and change of task

1. Select one method from the `INDEX.md` uploaded in this conversation that can fully address the current task. State its ID, name and method-pack path
2. The index is for selecting methods. If the complete text of the selected method has not been read, ask the user to upload the corresponding `packs/*.md` file, then proceed after receiving it
3. Reuse the full method when the same version has already been read and it fits the request. If a follow-up changes the objective, check the index again. If another method is needed, name its file and continue after it is uploaded
4. For additional data, corrections or revisions to the same task, keep using the original method. Do not ask for files already received
5. When the user requests several independent tasks, list the method packs needed for each and follow the user's chosen order. If no order is given, ask the user to select one task first
6. If the index has no suitable method, say so. Do not invent IDs or filenames, or pretend to have read other methods

## Data and sources

- Start with this conversation's attachments, background already provided and readable links specified by the user. If a link cannot be read, identify the missing content and ask for the file

- Distinguish product facts, brand claims, assumptions and unknowns. Preserve each number's period, unit, denominator and source location

- Keep examples quoted from teaching materials as examples. For current platform rules, read the official documentation itself or ask the user for the relevant official text
- Ask only for missing inputs that would affect this task's result. Do not ask again for information already supplied

# MK-256｜Product Image and Link Check


## Purpose

This Skill delivers: **Matching images and destination pages to products**

When IDs cannot be matched one-to-one, leave them unmatched rather than guess; do not invent a match rate without complete event samples

## Required Inputs

Catalog platform and link, image_link, and additional_image_link values by SKU or variant; product pages and authoritative product images; current read results and relevant official image and link specifications

## Method Steps

1. Preserve original link, image_link, and additional_image_link values by SKU or variant; read the URLs and final redirect destinations, recording response status and time
2. Verify the landing product and variant and inspect whether accessible images depict that product rather than another color or model; a downloadable image is not proof of a content match
3. Check format, dimensions, additional-image limits, and URL requirements against the actual platform’s current official specifications, recording sources and dates; leave missing access or specification evidence pending
4. Deliver access and matching results for each URL plus corrected URLs or missing-image requests; after an actual replacement, read back the page and image rather than treating a proposed URL as verified

## Calculation and Interpretation

Use product data for specifications and prices; verify catalog fields and disapproval rules during production

## Verification Cases

**MK-256-A1 | An image URL opens, but a blue SKU displays a red product**

Expected: Pass access and fail variant matching; request the correct blue image and read it back after an actual replacement
