# MK-251｜商品 ID 對照檢查

一般對話請上傳 `packs/mk-251.md`，其中已包含共用規則、本文及必要參考

## 工作目的

這個技能交付：**商品、變體與追蹤事件 ID 對照**

ID無法一對一匹配時保留未匹配，不猜對應；沒有完整事件樣本不捏造匹配率

## 必要資料

Feed 商品及變體 ID、實際 ViewContent／AddToCart／Purchase 事件樣本與其中商品識別值、網站 SKU 對照及相關事件時間

## 方法步驟

1. 目錄商品 id 必須與 Pixel／SDK 事件中的 content_id 一致；講義建議一般以 SKU 作統一標準
2. 核對 ViewContent、AddToCart、Purchase 的 content_id 是否能對上目錄商品
3. 對不上時先修事件或 Feed 映射，不用名稱近似猜商品

## 計算與判讀

商品規格與價格以商品資料為準；目錄欄位及拒登規則在製作時驗證

## 固定交付欄位

| 順序 | 欄位 | 填寫方式 |
|---:|---|---|
| 1 | 商品／變體 | 原始證據、方法中間結果或明確未知；不得補造 |
| 2 | 各來源ID | 原始證據、方法中間結果或明確未知；不得補造 |
| 3 | 欄位 | 原始證據、方法中間結果或明確未知；不得補造 |
| 4 | Feed值 | 原始證據、方法中間結果或明確未知；不得補造 |
| 5 | 網站值 | 原始證據、方法中間結果或明確未知；不得補造 |
| 6 | 更新時間 | 原始證據、方法中間結果或明確未知；不得補造 |
| 7 | 問題分類 | 原始證據、方法中間結果或明確未知；不得補造 |
| 8 | 修正位置 | 原始證據、方法中間結果或明確未知；不得補造 |
| 9 | 狀態 | 原始證據、方法中間結果或明確未知；不得補造 |

## 核對案例

**MK-251-A1｜只有 Feed，沒有事件樣本**

預期：列缺 ViewContent/AddToCart/Purchase 對照證據，不宣稱匹配通過
