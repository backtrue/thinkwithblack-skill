# MK-206｜Hero Post 候選篩選

一般對話請上傳 `packs/mk-206.md`，其中已包含共用規則、本文及必要參考

## 工作目的

這個技能交付：**含樣本量與多面向表現的候選**

歷史成功只支持候選與假說，不能把內容共同元素寫成已證實致勝原因

## 必要資料


可用原始資料：同Post ID分受眾任務的花費、曝光、點擊、成熟轉換與投放範圍

## 方法步驟

1. 以 Post ID 彙整花費、曝光、點擊、互動、有效訂單及訂單貢獻；保留受眾冷暖、優惠、頁面及可觀察期限，不把不同情境加總後排一個冠軍
2. 在相同任務與可比情境中，成交目標先看成熟有效成果及可承受成本；高 CTR／互動但沒有成熟成交支持，保留為吸引注意或教育候選，不列成交主力
3. 做脆弱性檢查：拿掉一筆最大訂單後是否從符合目標變成不符合；會翻轉者保留測試候選，列清楚依賴哪筆，不稱已跨受眾驗證
4. 多個原定目標受眾均有成熟且符合成本的結果，才列可在這些已觀察條件續用的主力；只有暖受眾成立就限暖受眾，不由總 ROAS 推到新客
5. 商品／優惠失效、退貨回補造成成果超標或新受眾不成立，撤回相應主力範圍。缺訂單對應時先補 Post ID 對應成果，不以任意花費額代替驗證

## 計算與判讀

CTR＝同範圍點擊／曝光；每成果成本＝花費／有效成果。四面向欄同列轉換、點擊、互動及跨情境重現情況；去掉最大單只是脆弱性檢查，不是統計檢定

核對例（假設資料）：兩篇同花 2,000 元，A 只有一筆 20,000 元大單，B 有多筆成熟訂單且符合既定成本；A 保留候選，B 可在已驗證受眾續用。B 回補大量退款後超標，改回測試或停用候選
