# MK-071｜客單轉換率敏感度分析

一般對話請上傳 `packs/mk-071.md`，其中已包含共用規則、本文及必要參考

## 工作目的

這個技能交付：**不同假設下的營收與利潤變化**

資源反推不等於預測或最佳配置；沒有可承擔上限時不自行決定真實支出

## 必要資料


可用原始資料：已知營收拆解、可執行改善方案、成本工時及原因紀錄

## 方法步驟

1. 把同期間營收、有效訂單、流量分母及客單對齊，先重算基線；若流量用人次，轉換就用該人次口徑的訂單率，不能混入另一表的使用者轉換率
2. 固定其他變數算各槓桿達標所需值，然後逐一接上可做的實際行動、成本、交期、庫存與支持變化的紀錄；代數上最小變動不等於最容易做到
3. 超過供貨量、已知可達轉換範圍或準備期限者，排除本期方案；兩方案目標成果相同，若一方案費用更高、時間更長且無其他已知優點，先選另一方案
4. 其餘依使用者目標比較情境貢獻與可行性，不擅設權重；兩者取捨需要未知成本才能決定時，只補該成本，已知算式與可排除選項先交
5. 實際優惠降低單筆貢獻、或增加客單同時降低成交率，聯動重算；原本最佳槓桿被新條件推翻時，換成仍達目標且可執行的候選

## 計算與判讀

營收 R＝流量 T×訂單率 C×客單 A；目標所需 C＝R目標／(T×A)，其他同理，分母為零不求解。貢獻＝訂單數×單筆淨收入扣變動成本－額外取得與實施費，再與固定費／目標比較

核對例（假設資料）：1,000 次到訪×2%×1,000 元＝20,000 元；要 30,000 元可把客單情境設為 1,500 元。若組合改價使成交率降為 1%，改算只有 15,000 元，撤回單靠客單便達標的建議
